엔진을 안써도 적용가능한 코딩 표준을 정리함


### 1. 구조와 가독성
- 헤더와 클래스는 읽는 사람 기준으로 정리한다
    - public → protected → private 순서
- 인터페이스가 구현보다 먼저 보이게 한다
- 한 줄에 하나의 선언만 둔다


### 2. 네이밍
- 타입/변수는 명사, 함수는 동사
- 의미가 분명한 전체 단어를 사용하고 과도한 약어를 피한다
- bool 반환 함수는 질문 형태로 작성한다
    - Is, Has, Should, Can 등
- 참조로 값을 써서 돌려주는 파라미터는 Out 접두사를 사용한다


### 3. const 규칙
- 수정하지 않는 모든 값에 const를 우선 적용한다
- 객체 상태를 변경하지 않는 멤버 함수는 반드시 const로 선언한다
- 순회/조회 목적의 인자는 const 참조를 기본으로 한다
- 반환 타입 자체에 const를 붙이지 않는다
    - 불변 의도는 const 참조/포인터로 표현한다
- move 대상이 되는 값에는 const를 붙이지 않는다


### 4. 함수와 반환
- 의미 없는 Out 파라미터 사용을 지양하고, 가능하면 반환값이나 구조체로 묶는다
- 함수 이름만으로 효과와 반환 의미가 드러나야 한다
- 한 함수는 하나의 책임만 가진다


### 5. 코멘트
- 무엇을 하는지가 아니라 왜 그렇게 했는지를 설명한다
- 자명한 코드에 주석을 달지 않는다
- 긴 주석으로 나쁜 코드를 덮지 않는다
    - 리팩터링이 우선이다


### 6. 람다
- 짧고 국소적인 로직에만 사용한다
- 캡처는 반드시 명시적으로 작성한다
    - 자동 캡처(`[&]`, `[=]`)는 예외적으로만 허용
- 람다가 길어지면 이름 있는 함수로 분리한다


### 7. 타입과 이식성
- 크기가 중요한 값에는 고정 폭 정수 타입을 사용한다
    - 예: `std::int32_t`, `std::uint64_t`
- 직렬화/네트워크/파일 경계에서는 int 사용을 피한다


### 8. 기본값과 초기화
- 멤버의 기본값은 선언부 초기화를 우선 고려한다
- 생성자마다 중복되는 초기화는 허용하지 않는다
- 빌드 비용이 큰 프로젝트에서는 초기화 전략을 명시적으로 합의한다


### 9. 표준 라이브러리 사용
- 표준 라이브러리를 쓸지 자체 구현을 쓸지 프로젝트 단위로 통일한다
- 같은 역할의 API를 혼용하지 않는다


### 10. 언어와 표현
- 모호하거나 공격적으로 해석될 수 있는 용어를 피한다
- 전 세계 개발자가 읽는다는 전제를 유지한다
